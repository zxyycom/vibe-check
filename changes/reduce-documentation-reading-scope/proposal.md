# Proposal

收敛当前项目与用户文档的单篇职责和阅读成本；本计划保存本轮实施范围。

## Why

前轮通过分段降低局部密度，却让部分页面更长。用户要求把审查扩展到全部项目与使用者文档，解决内容范围而非仅排版。

## Outcome

当前文档均经过按用途审查；读者能从入口找到完成任务所需的最小主线，精确契约保持完整且只有一个定义位置。

## Scope

### Intended Change

逐篇审查 README、AGENTS、docs 根说明、guides、checks、development、tooling、governance 和 testing 的当前说明。根据实际问题缩短、去重、重排或按独立任务拆分；无问题的页面保留，并在本计划记录结论。

### Resulting Impacts

同步导航、README、受影响的当前链接、Case owner 与发布/投影 registry。检查随包内容和新旧规则的完整承接；不把历史实体、Case 账本或机器材料机械改写为教程。

## Success Criteria

- 基线 41 篇当前说明均有明确审阅结果，改与不改能由阅读任务解释。
- 改动减少不服务当前任务的正文、重复规则或混合职责；拆分后的主线与详解可独立定位，未用更密排版伪造缩短。
- 公开配置、失败/取消、安全与权限规则保真；用户任务不依赖未发布页面。
- 受影响标题、Case、示例投影和随包路径闭合，独立审阅及完整 Gate 通过。

## Affected Owners

以文档导航的公开/内部 owner 为准：用户 API 与专题、逐项 Check 指南、内部开发设计、tooling、知识治理和测试维护。现有 registry、源码声明、schema 和 Case 继续拥有各自精确契约。
