# Design

以连续的 Gate 设计与建设决策为主线，示例证明工程判断如何落地，专题承接精确用法。

## Context

用户已确认整体调整方案并要求实施。工作从 main、干净工作区开始；前一轮 0.0.5 文档 Change 已结项，不恢复旧生命周期。文档规则由 `docs/tooling/documentation.md` 拥有，教程不复制精确产品契约。活动文档决策要求单一 README 入口、任务专题、中文主叙述、自然标题投影和消费者独立审查。

## Goals / Non-Goals

目标是让读者为自己的项目设计并实现可信、可维护、反馈高效的 Gate，能解释其检查边界、关系和改善选择。完整入口与深入能力的可访问性仍必要，但不是用能力清单替代判断主线。不改产品 API、不增加 CLI、不引入组合抽象、不做运行性能优化或 benchmark、不重新审查全部发布文档。用户已明确授权整理提交本次文档调整并完成 Change 结项；普通提交遵循当前 checkout 的受限 auto-push hook。

## Decisions

### Intended Change

1. 以具体项目的配置、测试和构建产物说明质量目标、证据与失败含义；先明确要证明什么，再选择已有能力。
2. 从独立验收结论推导 Check 边界，区分执行步骤、共享准备和质量判决。
3. 执行图是主体：共同产物的准备与消费者、成功依赖与终态观察、隔离、函数/命令边界、identity 和 cleanup。重复准备与层层包装经验直接服务这里的取舍。
4. 保留完整可运行项目入口，交代 root、environment、outputs、严格退出、本地与 CI 及任务范围；其它片段只说明当前设计判断所需变化。
5. 正确 Gate 之上依据实际成本选择增量、缓存和并发，按同条件测量和原证明能力验收，而非以减少工作量冒充无损加速。
6. 主指南负责设计与组合，现有专题负责精确 API 和完整深入用法。沿用 AI-ready 原则：当前目标、必要边界、自然中文、稳定标题和可恢复引用；不保留无新判断价值的重复提醒或迁移过程说明。
7. 在已完成第三轮设计主线之上，按用户追加的 AI-ready 复核整理正文：以适量子标题和自然段拆清多个判断，合并同义边界与编辑性对照，将片段运行约定置于入口上下文。保留可执行代码及必要协议、安全和失败约束；相邻 owner 只作局部衔接，不扩成全包文案重写。

### Resulting Impacts

- 示例源、Markdown 和标题投影必须一致；重新排版不能手改生成代码块。
- 修改演示断言时按测试策略及 test-design / test-evidence-review 核对证据边界，不将教学固定数值当性能测量。
- 验证以本任务影响为限：投影、链接、定向示例、installed documentation 和独立阅读；不自动运行全 Gate 或 release verify。
- 指南介绍的是用户的项目入口，不把本仓库 `bun run check`、budget、candidate preparation 作为消费者前提。
- 第三轮定向 Gate 确认指南不再触发行数 Finding，既有精确 waiver 产生 unused audit；移除该 waiver 并同步配置、配对测试、Case 与 owner。限额和选择范围保持，不新增或扩大豁免。

## Risks / Trade-offs

主线更完整可能增加篇幅，因此共用基础运行约定，避免重复契约或把全部场景叠加到首次示例。减少包装与共享准备必须保留退出语义、取消、进程隔离、材料身份和清理边界。更改随包内容后必须重新绑定本轮候选证据，不能沿用之前候选的审查通过结论。

## Open Questions

无影响实施范围的未决项；具体最窄验证入口在读取现有工具后确认。
