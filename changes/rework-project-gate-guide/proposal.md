# Proposal

重写构建 Gate 主指南，使读者能把项目质量目标转化为有依据的检查边界、执行图、项目入口与改善方案；本文为本次实施计划。

## Why

前两轮补齐了真实接入与可执行示例，并收敛篇幅和样式，但正文仍偏向能力场景目录。用户明确要求指南解释如何设计和建设 Gate，第三轮已建立连续的工程判断主线。本轮继续按 ai-ready-docs 复核密集段落、重复对照语句、迁移残留与 Markdown 层次，保持设计目标并改善阅读与使用。

## Outcome

读者能仅凭随包材料，为自己的项目从质量目标选择证据、划分独立检查、组织执行与隔离、落地本地/CI 入口，并依据测量改善成本；能解释为什么这样组织，以及怎样确认质量证明仍成立。

## Scope

### Intended Change

- 重写 `docs/guides/building-project-gate.md`：质量目标与证据、独立 Check 边界、执行图、项目入口、按成本演进和设计验收。
- 同步 README 的首次接入入口与受影响导航；保留专题 owner，不新增产品行为或框架。
- 沿用 ai-ready-docs 的语义与组织约束。主指南由 6.1 Terra 承担主要改动，长示例与精确 API 用法由相应随包专题承接，不为保留旧场景数量堆积内容。
- 本轮整理以正文和阅读层次为限：分清证据、Check 边界与实现选择，合并重复说明，将片段运行约定归回项目入口；相邻专题只修相关连接与重复说明，保持示例代码和公开契约。

### Resulting Impacts

- 修改受管示例的源文件和投影 registry，再生成正文；标题与链接同步迁移。
- 新接入示例取得成功、无效输入、退出码及项目根目录相关证据；既有深入示例保持可用。
- 实际候选包中的指南和示例需要定向验收及独立消费者审查；既有正式发布结论不自动覆盖新材料。
- 第三轮重写使指南不再触发行数 Finding；移除已无匹配的指南精确 waiver，同步配置、测试、Case 和 owner，保持限额与扫描范围。
- 深入示例移交现有随包 owner 后同步标题投影、引用和 Case 证明范围；保持可执行性，不靠丢失示例或安全边界减少篇幅。

## Success Criteria

- 每节围绕一个工程判断承接上一步结果，读者能从项目风险推导检查、关系与验收，而非只从 API 名称查例子。
- 有一份可独立运行的项目入口；其它例子服务当前判断。重复准备与多余包装经验融入执行组织；增量、缓存与并发由实际成本和证明责任驱动。
- 既有能力的必要使用与安全边界可从主指南及可访问专题恢复，完整示例和自动证明拥有明确归属。
- 相关投影、链接、示例运行及包内材料验证通过，独立复核无阻断发现。

## Affected Owners

- 文档导航、文档与包材料、用户使用者审查。
- 构建 Gate 指南、README、相关 Check 与 Run 专题。
- API 示例投影及 installed documentation acceptance。
- 产品 API 与发布流程不改变；内部 Gate 仅移除本指南已无匹配的精确 waiver，限额与扫描范围保持。
