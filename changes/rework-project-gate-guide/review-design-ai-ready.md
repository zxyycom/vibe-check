## 两类任务恢复

### 任务一：从质量目标到项目 Gate

1. **明确证据与判决。** 配置用真实 JSON 检查；项目测试、包大小、干净安装运行各自形成独立结论。合法 JSON 不证明业务语义，大小成功不证明可运行；无匹配文件、启动失败和 unavailable 均不形成放行证据。来源：主指南 9–24。
2. **选择共享与隔离。** 只有大小和运行验收确实消费同一个包时，才抽出一次准备；两消费者绑定同一次构建的身份/位置。大小失败不阻断另一验收，准备失败则两者不能通过。各自直接依赖 provider；失败后审计使用 observes，自身通过不挽回上游。来源：主指南 43–56。
3. **落实资源责任。** 准备 owner 指明 identity、可写者和最后消费者；普通摘要/路径用 canonical data，破坏性测试、不同运行时和冷安装使用隔离副本或独立准备。Run 外层 try/finally 在所有消费者结束/取消后清理；缩短包装链不能删掉取消、环境、输出或隔离边界。来源：主指南 58–66。
4. **接通入口并扩展。** 先按项目根目录建立真实 JSON 入口，只接受 `completed && aggregate === "passed"`；同一 script 用于本地/CI，CI 固定运行环境与 lockfile 并保留安装/检查非零退出。再逐项加入测试与产物验收；最小入口没有冒充整套目标已完成。来源：主指南 70–170。
5. **保留证明范围。** 未选项不属于本次证据，未知任务拒绝，前置项闭合，完整路径保留；优化从端到端测量出发，每项措施保留原失败对照。来源：主指南 182–208。上述答案在主指南中即可恢复，无需先把六篇专题读完再猜设计顺序。
