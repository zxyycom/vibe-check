# Proposal

本 Draft 规划公共 Core 路径—区域关系工具，以一次计算生成可共享的只读双向查询快照。

## Why

调用方需要查询文件所属区域及区域包含的文件。内部 `collectProjectFileSets(...)` 已提供区域到文件的集合，多个 Check 又各自构建反向索引；这些关系处理缺少 Core、随包能力和外部调用方可共同依赖的公共契约。

一次操作中的消费者应能共享同一份关系数据。采用无状态计算和只读结果，可以集中处理匹配与索引，同时由输入获取者管理新鲜度、由领域消费者解释成员数量。

## Outcome

调用方可从显式路径与具名区域规则，或已取得的实际区域成员集合，构造同一种关系快照：

- 双向查询路径与区域 IDs，保留零命中、重叠，并区分未知查询键和已知空结果；
- 同一次操作直接共享只读结果，查询复用内部索引且无 I/O；下一次操作重新提供输入并计算；
- 复用 Product 生效的共同 matcher；路径获取与筛选归输入 owner，Core 只计算给定路径的关系。

本 Change 独立交付 Core 契约、必要的内部复用与 package consumer 验收。
