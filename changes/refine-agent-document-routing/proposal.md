# Proposal

本 Change 根据已完成的路由走查和 AI-ready 审查，局部修正文档入口、当前流程与示例，并保持既有 owner 分层。

## Why

当前入口、owner 和指南共 59 份均可沿文档链找到，但文件可达不等于任务信息充分。走查发现提交副作用、内部文档和 Change 前置核对缺少定向入口；后续三位独立审查代理确认了无条件投影写入、未定义 Gate 档位、owner 承诺偏窄、错误引用标签及不完整的可执行示例。

当前分层和大多数负向边界仍有明确价值；修订应针对这些已证实的问题，不以字数、否定词或样式统一驱动全仓重写。

## Outcome

代理能从 AGENTS.md 按实际任务找到必要文档和验证入口，清楚区分入口摘要与完整规则 owner；
新增领域或调整文档位置时，有明确的路由维护位置，无需在多个入口重复维护同一规则。

## Scope

### Intended Change

- 补齐提交/hook、内部文档维护和 Change 前置核对的定向入口，并把已有 evidence README 文本引用改为可跟随的链接。
- 区分正文编辑与投影写入流程，按当前 fast/changed/all 语义修正 `required` 残留，校准 scanner owner 开头与输出 owner 引用标签。
- 在同页内调整 Scheduler、文件收集的规则与优化细节顺序，保留精确不变量、错误顺序与安全边界。
- 从受管源码补齐自定义 Check 的 Definition、Run 与结果读取，再同步 Markdown 和 JSDoc 投影；不改变产品行为或增加路由层。

### Resulting Impacts

- 改动标题、路径或入口说明时，同步直接引用与维护责任，避免形成第二份规则正文或索引。
- 保留公开契约、内部实现说明、Skill 方法和治理载体的既有边界；不改变随包范围、产品行为、工具入口或验证义务。
- 通过代表性任务的语义走查及仓库文档检查分别验收，不把链接可解析当作路由充分性的证明。
- 示例 region 扩展会更新公开 `defineCheck` JSDoc 与随包指南；须核对投影、安装后示例执行及包材料，不手改生成片段。

## Success Criteria

1. 代表性任务均能从实际入口找到必要 owner、前置条件、授权边界及适用验证；答案可以回指具体文本，而非依赖审查者补充解释。
2. 每项修正都有对应的任务缺口与复核结果；未发现实质缺口的路径不为形式统一而改写。
3. 完整规则仍由唯一 owner 承接；入口摘要有清楚引用，新增领域或移动文档时能确定该更新哪一层路由。
4. 受影响引用及机械检查通过，语义审查与机械证据分开记录；无法覆盖的消费环境或任务明确保留为限制。
5. 文档使用当前 Gate 选择术语；纯正文编辑不默认进入投影写入；自定义 Check 示例仅凭公开片段即可执行并判断预期结果。
