## Implementation

- [ ] 1.1 实现 recursive `Check` authoring/type surface：independently optional `execution` / `checks`、optional `recordTypes -> []` normalization、direct context/result/reason types、Record/reference reporter、双 overload `defineCheck` 和 closed runtime validation。接受 empty information-only node，只发 non-blocking Definition warning。
- [ ] 1.2 实现 scheduling normalization 与 Task projection：missing/exact/clear/marked `inherit(add/remove)` for `dependsOn`/`mutex`、nearest-explicit `maxParallel`、canonical effective collections、one executable Check -> one Task/one-Task scope。复用 generic pre-work graph validation；不增加 alias、subtree pool 或 authored-order semantics。
- [ ] 1.3 迁移 Run、Core 和 policy handoff：每个 execution node 直接接收 `{ options, project, records, signal }`，形成一个 outcome/RecordSink；callback settle 时关闭 reporter、解析完整 Record identity 并在 Task settlement 前验证 generic reference candidates，snapshot 后只组装已验证 facts。映射全部 declared/Product reasons，删除 applicability path、TaskPlan factory/leaf/completion、group dependency expansion、source-specific runtime lookup 和多 Task Check layout。
- [ ] 1.4 将 `duplicateDetection`、`fileMetrics` 与 `functionMetrics` 迁移为完整普通 Check values：options 包含 scanner command 与现有 thresholds，execution 使用 current options/project context。删除 OperationalDependencies、Run override/environment precedence owner、`replace` / `append`、patch/parser/materializer files 和 exports；保留 scanner adapter protocol、exact-scope、cache 与 safe failure semantics。
- [ ] 1.5 迁移 final public inventory、stable docs、schemas/examples、semantic Cases 与 [`scripts/quality/project-definition.ts`](../../scripts/quality/project-definition.ts)。Reference examples覆盖 information root、execution-with-children、typed option-aware child、direct context/results、Record/reference reporting、native nested spread 和全部 inheritance states；同步 downstream package handoff，不在本 Change 实现 package build/publish。
