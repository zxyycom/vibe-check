## 目的
- 维护者能够从导航定位行为与流程 owner，不必先阅读无关领域才能完成修改和验收。
- 文档能持续增长，同时保留必要的设计推导、精确约束与局部使用上下文。

## 背景
- 用户指出内部文档的目录、命名和篇幅仍影响阅读与维护，授权一并调整。
- 文件长度不是独立职责的证据；按数字切页可能把共同规则拆散，也可能形成重复摘要和多个 owner。
- 随包用户说明与内部维护说明有不同阅读任务，本次内部组织不能改变发布集合或删减用户所需解释。

## 决策
- 采用: 内部文档按产品开发、仓库工具、知识治理和测试等实际维护职责分组；文件名指出中心对象，不建立只有分类意义的多层父目录。
- 采用: 文档导航继续是维护任务总路由，目录不各自维护重复索引；具体路径由当前导航与 owner 文档承接，不把文件清单固化在长期决策中。
- 采用: 长度只触发阅读负担与职责审查。只有内容拥有独立触发任务、主承诺和维护责任时才拆分；共同必读的约束可以保留在同一长文中，不设行数或页数硬阈值。
- 采用: 拆分后的 owner 完整承接原有规则和必要设计理由，跨 owner 通过有明确用途的链接连接；不复制整段规则来让每篇看似自足，也不要求使用者依赖未声明的前置知识。
- 采用: 迁移同步当前导航与引用，不留下第二份可编辑规范正文；历史证据中的形成时路径不因当前目录调整而重写。
