## 目的

- 让简单 admission heuristic 的频繁演进主要在可复现的虚拟负载中完成，降低真实执行成本，同时覆盖未知用户可能遇到的常见极端场景。
- 以整体完成时间为首要结果，在不牺牲该结果的基础上减少累计 Task 槽位时间和各命名资源单位时间；不推断用户业务重要性。

## 背景

- 现有公开 AdmissionGraph / AdmissionState 可以验证假设 select/settle，但不执行 Check、不推进时间，也不预测资源竞争后的实际速度。
- 固定时长重排不能表达并发竞争造成的工作效率变化；只用真实 Gate 调参则成本高，并可能把源码、history、缓存与环境变化混为算法效果。
- 用户确认以典型场景覆盖和无明显退化为本轮采用依据，不要求真实 workload 达到加速百分比；少量真实运行仍需校准模型和检查最终接线。

## 决策

- 采用: 仓库私有虚拟测量环境在公开 immutable admission state 之外拥有虚拟时间、工作量、推进速度与随机源；准入、依赖、scope、mutex、命名资源占用和结算合法性继续复用 Product，不复制 reducer，也不为模拟加入 Product 特权或第二 Gate process entry。
- 采用: 常规模型默认未声明资源的任务只承受自身波动；共享同一命名资源的并发任务默认存在效率损失，资源不相交不自动相互减速。减速幅度是待校准假设而非容量契约，验证同时包含零、弱、强竞争和模型失配场景；不能用声明本身证明现实因果。
- 采用: running 集合变化时重新计算所有相关任务的推进速率，以虚拟事件推进而非真实 sleep；随机条件按场景、重复轮次与 task 稳定绑定。基线与候选共享相同外生条件；策略只能读取正式公开上下文与可比较预测输入，不取得真实剩余工作量或未来随机结果。
- 采用: 整体完成时间为主，槽位累计占用与每种资源的 units × time 分别作为次指标，不把不同资源无权重相加，也不以降低并发峰值替代结果。不建立用户关键任务或延迟保护选项；critical-path score 仅是内部完成时间启发式。
- 采用: 频繁方案比较以有限、可解释的典型场景为主，采用前固定场景、随机条件与回归判断口径；不要求每项都加速，不用平均收益掩盖约定场景的明显退化。策略计算成本用真实宿主时钟单独测量，虚拟时间不证明该开销。
- 采用: 调查分别记录隔离任务与正式全量运行的时间口径、版本、样本和混杂因素，用证据决定模拟波动，不把并发慢化直接当独立随机噪声。参数化共享闭包 Check 只承担少量真实生命周期集成证明，真实 workload 承担少量模型校准与最终验证，不能被纯模拟替代。
- 采用: 小范围候选不足以满足约定验收时保留基线并交付不采用依据，不自动扩大为深层搜索、模型重建或通用平台；具体 Change 的收尾、发布依赖和实施授权仍由当前任务与 Change 承接。
