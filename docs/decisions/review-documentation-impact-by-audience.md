## 目的
- 用户能仅凭随包材料正确使用能力，维护者能恢复职责、约束和设计依据。
- 使每次行为变化的文档影响可复核，而不是把同步责任留给维护者记忆。

## 背景
- 同一能力的使用方案和内部设计有不同问题脉络、术语与解释深度；强制合并会使任一读者缺少必要信息。
- 当前示例投影、材料清单和链接校验只能验证结构与执行事实，无法证明手写语义的完整同步。
- 项目由 AI 维护，需要把实施与文档语义审查分开，而不是再增加无人维护的功能文档账本。

## 决策
- 采用: 用户文档拥有可独立使用的任务说明，内部文档拥有设计和维护解释；允许为各自用途重述共同承诺，不因同主题或措辞相近删除必要说明。
- 采用: 清理无独立用途的重复清单、数字和规则副本；共同承诺应明确范围并保持一致，但不要求两种叙述逐字一致或由模板互相生成。
- 采用: 变更验收在现有 Change 或局部任务交付中记录用户可见变化、内部设计影响、文档落点或无需修改的理由及实际验证，不建立平行文档状态账本。
- 采用: 由非实施代理依据实际 diff 与相关行为证据反查文档影响；重要深入能力另以仅持随包文档的代表性使用任务检验可理解性。审查不可用时明确未覆盖边界，不把实现者自查当作独立审查。
- 采用: 机械校验继续负责材料、链接、示例与可执行契约；文档文件已修改、哈希变化或校验通过均不能证明自然语言已同步。
