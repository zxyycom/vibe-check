# v3 bounded candidate: historical experiment design

This records the static design after the v2 window on 2026-10-12, not the final implementation. The A0–A5 attribution matrix below was proposed, not executed as a complete matrix. Final v3.1 adoption, corrections and evidence are owned by the [investigation report](../../evaluate-bounded-tokenizer-optimization.md). Statements about pending work below describe that design point.

## Narrow semantics

1. Preserve the original full-source RegExp compilation at first generator consumption, before any yield/factory call, including malformed addition errors. Keep flags, branch order, normalization, macro and callback execution untouched. No template regex rewrite or parity-based parsing.
2. A comment-tail risk exists only if `source.lastIndexOf('/*') >= 0 && source.lastIndexOf('/*') > source.lastIndexOf('*/') - 2`. Otherwise every possible opening has a closing delimiter at least two code units later; the branch remains satisfiable whenever its opening is reached. A false-positive can occur when the last opening is swallowed by an earlier whole token; false-positive costs are allowed, semantic changes are not.
3. If comment-tail risk is false and the caller has no fixed template branch or no raw backtick, use the original native matchAll loop with no per-token cursor/boundary work. Pre-scans still add finite cost and must be measured.
4. For templates, only consider omitting the template branch when the next matching cursor is exactly the last raw backtick. If a complete token has advanced beyond that backtick, the branch cannot be attempted again, so keep the existing regex and do not construct a reduced regex merely because cursor crossed it. Earlier raw backticks that might make the template regex costly remain conservatively unchanged.
5. Full-source cursor remains essential. The fixed combined regex ends in dot with `s,u`, which covers each code point, so native matchAll must match at current cursor, not first jump over whitespace to an opener. This must be checked against generated combined-pattern shape and all current reader additions, not assumed from ordinary examples. Zero-width AdvanceStringIndex may pass a backtick without consuming it exactly as baseline does; factory mutation of token text must not control raw cursor. Any combination that invalidates guaranteed coverage must retain the earlier conservative switch (or original matcher), not silently use exact-cursor switching.
6. For comments, keep conservative omission only once cursor is past last possible closing start and static tail risk exists. Do not compile a reduced pattern for normal closed-comment-only files. Lazy reduced compilation may still occur when tail opening is inside an already consumed string/template; that false-positive can be narrowed later without turning v3 into a parser.
7. Build invariant fragments once per invocation (same normalization, symbols, base string); compile original once and reduced pattern only when needed. Keep `(?!)` branch placeholder in the primary minimal candidate pending independent evaluation: removing a whole first branch can alter semantics of arbitrary addition not starting with `|` and capture numbering. Avoid broad source-string surgery.

## Independently controlled attribution (frozen imports/texts, no simultaneous timing)

- A0: unchanged original native matcher, oracle/baseline.
- A1 prep-only: last delimiter/opening scans, but exact original pattern and loop. Isolates scan cost; no candidate speed claim.
- A2 construction-only: create exactly the extra full/reduced pattern texts/RegExps required by v2 at the corresponding invocation stages, discard them and use original matcher. This isolates extra construction approximately, but regex caches and added control logic mean costs are not additive proof.
- A3 monitoring-only: original native pattern, update raw cursor and evaluate candidate boundary after each match but never switch or reconstruct. Isolates cursor/branch overhead, not engine rewriting.
- A4 shape-only: on inputs where omitted comment/template branch is independently impossible for the whole remaining matching interval, compare original vs reduced with the v2 `(?!)` placeholder using the same native loop and no per-token monitors. Also prepend a capture-free always-failing alternative to unchanged original pattern to check whether prefix shape changes optimization. The latter is a diagnostic perturbation, not exact attribution or an adoptable patch.
- A5 v3 integration: safe-file original fast path + lazy switch at actual tail boundary + prebuilt fragments. Feature switches for safe fast path, lazy no-crossed-template compilation, fragment reuse, and cursor monitor allow leave-one-out comparisons on the same frozen legal corpus. Do not fit raw scan results to Product Run improvement.

## Inputs and gates before any adoption request

- Reuse frozen 526-file legal corpus, fixed 348-module baseline and v1/v2 evidence. Node24.18 primary fresh-child AB/BA, Bun independent, external hard deadlines and explicit bounds. Avoid claims of stable improvement from four Bun samples.
- Representative small partition: no opening/closing comments; normal comment only; normal template only; both normal closed prefix forms; whitespace/CRLF/C0 directly before last unterminated opener; pure malformed tail; quoted/escaped delimiters; complete token swallowing last opener; comment overlap `/*/`, `/*/*/`; empty/astral/unpaired-surrogate/zero-width factory cases.
- Before timing A5: complete raw text/UTF16 offset/LF line + final-stream differential (751 inputs + 16 direct zero-width/custom factory matrices), all existing six source/lifecycle tests outside performance samples. Add partial-consumption/factory throw/iterator-return/invalid-addition probes in tmp before changing product tests; preserving laziness must not be inferred only from whole-input metrics.
- Full-source generated regex coverage proof is mandatory for exact-cursor template switch. No substring, no delimiter parity heuristic, no external engine, no default timeout, no cancellation-return change.
- If A5 still regresses legal Node or leaves original pathological prefix sample unsolved, retain explicit rejection/partial-fix evidence; do not rename it third optimization completed. Product/source identity/deviation/Case/package acceptance remains downstream of a successful Phase A and independent adoption review.

## Status at design time

Reviewed statically on 2026-10-12 after the v2 window. At that point the design had not been measured; subsequent v3/v3.1 implementation and adoption are recorded in the report. This historical plan does not authorize another experiment window.

## Additional conservative template cost dispatch (static assessment)

The fixed TEMPLATE_LITERAL outer repetition has three alternatives: backslash plus one character; `${` plus an interpolation body and `}`; a single character excluding backtick/backslash. On the suffix after the last raw backtick, absence of raw `${` makes the interpolation alternative impossible. The remaining escape and single-character alternatives have disjoint first characters and deterministic widths (two code units/code points for escape vs one code point), so they do not create the repeated interpolation-vs-ordinary-character decomposition responsible for the observed growth. Keeping the original regex for this suffix still permits linear fallback/backtracking; it is not a promise of constant time or a bound for attempts beginning before the last backtick.

Therefore `templateTailRisk = hasFixedTemplate && lastTick >= 0 && source.indexOf('${', lastTick + 1) !== -1` is a conservative COST dispatch: if false and comment risk is false, use the untouched original native loop. If true, use guarded tail switch. Raw escaped/quoted `${` may over-trigger monitoring, which is allowed. The test does not classify syntax, does not remove branches itself, and does not make earlier-template risks safe. Counterexamples with problematic earlier opener + raw backtick inside interpolation string must retain the documented partial-fix boundary.

This filter is preferable to raw backtick presence for minimal v3: it should avoid per-token overhead in ordinary closed-template files whose remaining source has no interpolation start. It preserves normal-prefix+`${...}` unterminated-tail coverage, unlike global absence-of-closing guards. Node legal corpus and additional adversarial variants must still verify actual dispatch membership/cost and complete token/lifecycle parity before adoption. No timing has established a benefit yet.

Minimal v3 integration now consists of (1) the two static risk filters, (2) original native fast path when both false, (3) guarded native matching for true risks with lazy pattern construction and no construction merely after a complete template crosses lastTick, and (4) unchanged original regex/normalization/source anchors/factory semantics. Shared per-invocation pattern-fragment reuse is a separately controlled experiment, not bundled without attribution. `(?!)` remains unchanged initially; shape diagnostics can decide whether a later equally bounded change is warranted.
